# Follow-ups from the native export and lexical search

Recorded on 2026-10-02 for stage 2 of the Rust port. Each is an edge case left as is; "verified" means observed or read, not reproduced in a user journey.

- `crates/daemon/src/search/query.rs` `excerpt`: a snippet longer than 200 UTF-16 units cut inside an emoji ends in half of it. The TS CLI prints that as U+FFFD in text, CSV and table output (as Rust does) but as a `\udXXX` escape in `--format json`; Rust's JSON has the U+FFFD character. Verified by reading Bun's behaviour; needs a snippet over 200 units with an emoji at unit 200.
- `crates/daemon/src/search/chunks.rs` and `query.rs`: the chunk bytes for a split surrogate pair and the 64-byte threshold below which Bun reads invalid UTF-8 as `""` were observed with Bun 1.3.14 (`select hex(?)` and `cast(x'…' as text)`). Another Bun may differ; `parity_export_search.rs` re-checks both against the installed Bun. The TS CLI goes away at stage 6, after which only the Rust behaviour matters and both quirks can be dropped (bump `CHUNK_VERSION`).
- Ranking against BK's live TS CLI: bm25 depends on the whole FTS table. The daemon indexes active and archived chats; the TS CLI indexes only the scopes someone searched or indexed, and keeps chunks of chats it hasn't re-indexed since they changed. So the same query can score, and occasionally order, differently from the installed TS CLI even though both rank the same way over the same chunks (the parity harness gives both all chats). Verified by reading.
- `export -` (ids on stdin) isn't supported natively; the TS CLI's `selectOne` would read stdin. Not documented for `export`. Verified by reading.
- `export --output=` (an empty value) writes the title-named file; the TS CLI treats an empty `--output` as unset and prints to stdout. Unverified in the TS CLI.
- `export` of a chat ChatGPT no longer has prints `404 from /backend-api/conversation/<id>` without the response body the TS CLI appends, by the no-bodies rule. Intentional.
- `search --format table` measures columns with the `unicode-width` crate, where the TS CLI uses `Bun.stringWidth`. They agree on emoji (with skin tones, ZWJ sequences and VS16), CJK, combining marks and zero-width spaces (`search_cmd.rs` tests); rarer sequences may differ by a column. Unverified beyond those.
- `crates/daemon/src/search/indexer.rs`: a batch read in flight when an explicit `sync` starts can retry a 429 while the sync's client is attached to the progress reporter, so that client may see the indexer's `rate limited by ChatGPT; waiting …s` line. Verified by reading; cosmetic.
- The indexer retries a chat ChatGPT didn't return after an hour, for as long as it's in the index; `daemon status` counts them as "set aside for an hour". A timeout or dropped connection sets nothing aside: it ends the run, and the run after the next pass tries again. A chat deleted in the browser stays in the index until a full sync (see `nightly-full-sync.md`). Verified by reading.
